# Opt-in generated XML evidence — increment 11

Development only. No tenant inspection, document repair, schema migration,
deployment, worker restart or remote request was performed. Live generation,
submission, UUID/ICV allocation and cryptographic algorithms are unchanged.

## Explicit scope and permissions

The internal, non-whitelisted `inspect_saved_invoice_artifacts` keeps its default
attached-file behavior. Explicit `include_generated=True` additionally requires
the standard Frappe **System Manager** gate (or Administrator), as loose files
have no File-record ACL. Invoice and Company read permissions still apply.
Non-boolean options fail with an Arabic-translated message. This is not a new
HTTP endpoint, UI action or automatic background job.

The option reads only the exact known live signed-file location:
`private/files/final_xml_after_indent_{invoice_name}.xml`, written by
`sign_invoice_first.structuring_signedxml`. There is no glob, directory scan,
unsigned/intermediate XML read, URL fetch, filename sanitization or URL decoding.
Invoice names containing slash, backslash or NUL, or equal to `.`/`..`, are
reported unsafe instead of being transformed into a different path.

Default attachment mode and generated mode share one bounded exact-byte reader.
Only regular local files up to 5 MiB are read; leaf symlinks, traversal, special
files, invalid XML and ambiguous metadata remain static diagnostic failures.
Raw XML, filesystem paths, parser errors, auth and private keys are not returned.

## Provenance limits

The legacy basename has neither DocType nor Company. A same-named Sales Invoice
and POS Invoice can refer to one mutable path. A read-only existence query for
the other DocType reports `generated_doctype_ambiguous`, without returning that
document's Company or fields. Matching ID/UUID/ICV/seller metadata does not clear
that ambiguity. The diagnostic does not change the legacy writer or choose a
document owner automatically.

`generated.status` distinguishes `PRESENT`, `MISSING`, `UNREADABLE`, and
`UNSAFE_NAME`. Missing files are absent evidence, **not** proof that no issuance
or acceptance occurred, and do not invalidate an otherwise consistent attached
artifact. A current generated path may have been overwritten or removed; this
is not a historical ledger. Reports are not an atomic concurrent-worker snapshot.

Generated bytes use the same identity inspector and exact SHA-256 comparison as
attachments and embedded response XML. Matching bytes retain separate sources;
different parsed byte fingerprints produce `CONFLICT`, even when metadata agrees.
A legitimate original/cleared difference still needs provenance reconciliation.
No source is selected, overwritten, removed, signed or submitted.

`include_history=True` and `include_generated=True` compose: response and counter
observations remain read-only and retain their existing permissions and checks.
`generated_inventory_complete`, `signature_verified`,
`remote_acceptance_verified`, and `replay_authorized` remain false; the combined
history mode also retains `history_complete=False`.
